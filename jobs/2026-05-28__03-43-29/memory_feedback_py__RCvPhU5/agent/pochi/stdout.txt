# Submit Memory Feedback with the Mem0 Platform Python SDK ## Background Mem0 is a managed memory layer for LLM agents. After storing memories with `MemoryClient.add(...)`, products can submit feedback on individual memories using `MemoryClient.feedback(memory_id, feedback, feedback_reason)` so that the underlying ranker can improve. The feedback enum supports `POSITIVE`, `NEGATIVE`, and `VERY_NEGATIVE`. In this task you must write a small Python program that ingests a short conversation into Mem0, retrieves the extracted memories for a unique scoped user, submits one feedback record per memory (cycling through the three feedback types), and writes a structured log so the run can be audited. ## Requirements * Use the Mem0 Platform Python SDK (`from mem0 import MemoryClient`) — the script must hit the real managed API using the `MEM0_API_KEY` environment variable. Do not mock the SDK. * Read the run identifier from the `ZEALT_RUN_ID` environment variable and use it to derive a unique `user_id` so concurrent runs do not collide. * Add a short, deterministic conversation (provided below) to Mem0 under that scoped `user_id`. * After the add call, list the resulting memories for the user using `client.get_all(...)` so you can capture the server-assigned memory IDs. * For each stored memory, submit one feedback record using `client.feedback(...)`. Cycle through the feedback types in this order — first memory: `POSITIVE`, second: `NEGATIVE`, third: `VERY_NEGATIVE` — and provide a non-empty `feedback_reason`. If Mem0 produces fewer than three memories from the conversation, cycle through the feedback types in the same order across whichever memories do exist. * Write a structured log file recording every feedback submission so it can be verified. ## Implementation Hints * Build the scoped user with the pattern `feedback-user-${ZEALT_RUN_ID}`. * Memory extraction in the managed API is asynchronous; after `client.add(...)` returns you may need to wait briefly (poll `client.get_all(...)` until it returns memories, or sleep) before the IDs are available. * The Python SDK exposes a `feedback(memory_id=..., feedback=..., feedback_reason=...)` method that returns a JSON-serialisable dict containing the feedback `id`. * Use `client.get_all(filters={"user_id": "feedback-user-${ZEALT_RUN_ID}"}, version="v2")` so the response is the v2 envelope with stable IDs. * Keep the script idempotent enough to retry on transient failures; verification will only inspect the final log file and the live state in Mem0. ## Conversation to ingest ``` role=user content="My name is Robin and I'm planning a trip to Kyoto next April." role=assistant content="Lovely!
