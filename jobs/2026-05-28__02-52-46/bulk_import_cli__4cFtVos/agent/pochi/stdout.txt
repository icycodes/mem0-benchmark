# Bulk-Ingest User Preferences Using the Mem0 CLI ## Background A product team is migrating recorded user preferences into Mem0 so their support agent can recall them across sessions. They prefer to use the official `mem0` command-line interface (rather than calling the REST API or an SDK directly) so the same workflow can run in CI jobs or local shells. You will build a small shell-driven workflow that authenticates the CLI, ingests a batch of preference statements for a single user, searches the resulting memories, and produces a log file that records what was created. This task targets the **Mem0 Platform** (managed) via the `mem0` CLI. The Mem0 API key is provided through the `MEM0_API_KEY` environment variable. ## Requirements * Install the official Mem0 CLI in the environment (either the `mem0-cli` Python package or the `@mem0/cli` npm package; the binary on `PATH` MUST be named `mem0`). * Use `MEM0_API_KEY` (already exported) so the CLI can authenticate against the managed Mem0 Platform without an interactive `mem0 init` prompt. * Read the current `run-id` from the `ZEALT_RUN_ID` environment variable. All memories produced by this task MUST be scoped to the user id `harbor-bulk-import-${run-id}` to avoid colliding with other concurrent task runs. * Ingest the following four preference statements as **separate memories** for that user, in order, using the CLI's add command: 1. `I prefer dark mode in every application and avoid bright UI themes.` 2. `I work in the America/Los_Angeles timezone and prefer afternoon meetings.` 3. `I am vegetarian and have a severe peanut allergy.` 4. `My primary programming language is Python and my editor is Neovim.` * After ingestion, run a single `mem0 search` query for the text `dietary restrictions` scoped to the same user, restricted to the top 5 results, with structured JSON output. * Append a log entry to `/home/user/bulk-import/output.log` for each ingested memory and for the search result. The log file format is described in the Acceptance Criteria. ## Implementation Hints * The `mem0` CLI honours the `MEM0_API_KEY` environment variable directly, so you do not need to run an interactive `mem0 init`. * Use the CLI's structured JSON output mode (for example via the global `--json` / `--agent` flag, or `--output json`) so that ingestion responses can be parsed for the new memory IDs without resorting to regular expressions over coloured human output. * The CLI's `add` command can take the memory text as a positional argument together with `--user-id`. Repeat the command for each preference instead of relying on a single bulk `import`, since each preference should be tracked as its own memory. * Use `jq` (or equivalent JSON parsing) to extract memory ids from each `mem0 add` response when writing the log. * Make the workflow idempotent enough that re-running it would not break a fresh re-evaluation: the log file must be (re)created from scratch on each run. ## Acceptance Criteria * Project path: /home/user/bulk-import * Ensure the real ingestion is executed against the Mem0 Platform and the log artifact exists. * Log file: /home/user/bulk-import/output.log * The `mem0` CLI binary MUST be available on `PATH` and report a non-empty version when invoked as `mem0 --version`. * All memories created by this task MUST be scoped to user id `harbor-bulk-import-${run-id}` where `run-id` is read from the `ZEALT_RUN_ID` environment variable. * Exactly four memories MUST be created via the CLI's add command for the run-scoped user. * The log file MUST contain the following lines, in this order: * A single header line: `User ID: harbor-bulk-import-<run-id>` * One line per ingested memory, in the order listed in Requirements, of the form: `Added memory: <memory_id>` * `<memory_id>` is the id returned by the Mem0 Platform for that ingestion (extracted from the CLI's JSON response). * A line summarising the search results of the form: `Search hits: <n>` where `<n>` is the integer count of results returned by `mem0 search "dietary restrictions" --user-id harbor-bulk-import-<run-id> --top-k 5` in JSON mode.
