# Mem0 Group Chat Memory Attribution ## Background You are helping a product team capture decisions from a multi-participant planning conversation. Mem0's managed **Group Chat** feature automatically attributes memories to individual speakers when each message carries a `name` field: user messages become memories scoped to the speaker's `user_id`, and assistant/agent messages become memories scoped to that speaker's `agent_id`. Your job is to wire up a Python script against the Mem0 Platform (`MemoryClient`) that ingests one such conversation and emits an attribution log that the verifier can audit. ## Requirements * Build a Python program that runs end-to-end when invoked once. * Authenticate the Mem0 Platform client with `MEM0_API_KEY` from the environment. * Read `ZEALT_RUN_ID` from the environment and use it to suffix every shared identifier so concurrent trials do not collide. * Construct an in-memory multi-turn conversation that contains: * At least **three distinct user participants** (e.g., Alice, Bob, Charlie) — each message **must include the `name` field** alongside `role` and `content` so Mem0 detects the group-chat scenario. * At least **one assistant participant** that also carries a `name` field so it is attributed as an `agent_id`. * Content that is concrete and distinctive per speaker (each speaker should express at least one preference, decision, or fact that Mem0 can extract). * Send the whole conversation through `client.add(...)` in a single call, scoping it to a per-session `run_id`. * After ingestion, retrieve memories per participant and write an attribution log file. ## Implementation Hints * Install `mem0ai` and use `from mem0 import MemoryClient`. * The Group Chat feature is documented at https://docs.mem0.ai/platform/features/group-chat. The `name` field on each message becomes the `user_id` (for `role="user"`) or the `agent_id` (for `role="assistant"`). * Use a per-session `run_id` such as `planning-<ZEALT_RUN_ID>` when calling `client.add(...)` so all memories from this session can be grouped together. * Suffix participant names with the run id (e.g., `alice-<ZEALT_RUN_ID>`) so they become uniquely scoped user/agent identifiers. * Memory extraction is asynchronous on the Platform; after `add`, poll `client.get_all(...)` with the appropriate filters until memories appear (with a reasonable timeout) before writing the log. * `get_all` on v2 requires filters; you can pass `filters={"user_id": "alice-<run_id>"}` or `filters={"agent_id": "facilitator-<run_id>"}`. ## Acceptance Criteria * Project path: `/home/user/group_chat` * Ensure the script is executed against the real Mem0 Platform and the log artifact exists. * Log file: `/home/user/group_chat/output.log` * The script must read the value of `ZEALT_RUN_ID` from the environment and use it to suffix every Mem0 identifier (participant names and the session `run_id`). * The Mem0 call must use the managed Platform client (`MemoryClient`) authenticated with `MEM0_API_KEY`. * The conversation submitted to Mem0 must include at least three distinct user participants and at least one assistant participant, with the `name` field set on every message. * The log file must contain, in any order, all of the following lines (one per line, exact prefixes): * `Session: planning-<run_id>` — exactly once, where `<run_id>` is the value of `ZEALT_RUN_ID`. * `User memory: <user_id> :: <memory_text>` — at least one line per distinct user participant (so at least three such lines total). `<user_id>` must be the run-id-suffixed participant identifier. * `Agent memory: <agent_id> :: <memory_text>` — at least one line for the assistant participant. `<agent_id>` must be the run-id-suffixed assistant identifier. * After the script runs, Mem0 must contain memories attributed to each user participant and to the assistant participant, queryable via `client.get_all(filters={"user_id": ...})` and `client.get_all(filters={"agent_id": ...})`.
