# Mem0 Platform — Structured Memory Export with Pydantic Schema (Python) ## Background A customer-success platform stores ad-hoc notes about each lead in **Mem0 Platform**. The analytics team wants a reproducible way to flatten those notes into a structured **professional profile** record for each lead so they can be loaded into a downstream warehouse. Mem0's **Memory Export** feature does exactly this: you submit a Pydantic JSON schema plus filters, Mem0 spawns a background job that extracts the matching memories and returns a single structured object that conforms to the schema. Your job is to write a Python script that: 1. Ingests several conversational memories about a single lead into Mem0 Platform using entity-scoped filters. 2. Defines a Pydantic schema describing the desired profile output. 3. Submits a memory export job for that lead. 4. Polls the export status until the structured data is available. 5. Persists both the raw export response and a normalized profile artifact. Relevant Mem0 documentation: * Memory Export (overview): https://docs.mem0.ai/platform/features/memory-export * Create Memory Export API: https://docs.mem0.ai/api-reference/memory/create-memory-export * Get Memory Export API: https://docs.mem0.ai/api-reference/memory/get-memory-export * Entity-Scoped Memory: https://docs.mem0.ai/platform/features/entity-scoped-memory * V2 Memory Filters: https://docs.mem0.ai/platform/features/v2-memory-filters * Platform Python Quickstart: https://docs.mem0.ai/platform/quickstart ## Requirements * Use the **Mem0 Platform Python SDK** — specifically `from mem0 import MemoryClient`. Do NOT use the open-source `Memory` class. * Read `MEM0_API_KEY` and `ZEALT_RUN_ID` from the environment. Fail fast with a clear error message if either is missing. * Derive `${run-id}` from `ZEALT_RUN_ID` and use it on every entity ID so concurrent runs do not collide: * `user_id = "lead-${run-id}"` * `agent_id = "csm-${run-id}"` * `run_id = "intake-${run-id}"` * Ingest the following **four** independent memory writes via `client.add(...)`. Every `add` call MUST include all three entity IDs above. The `messages` payload for each call MUST be sent verbatim: 1. `[{"role": "user", "content": "Hi, my name is Priya Shah and I work as a Senior Data Engineer at Helios Robotics."}]` 2. `[{"role": "user", "content": "I'm based in Bengaluru and I've been at Helios for about 4 years."}]` 3. `[{"role": "user", "content": "I have a Master's degree in Computer Science from IIT Bombay."}]` 4. `[{"role": "user", "content": "You can reach me at priya.shah@helios-robotics.example and my LinkedIn handle is priya-shah-de."}]` * After ingestion, define a Pydantic `BaseModel` named `LeadProfile` with the following fields: * `full_name: Optional[str]` — the lead's full name. * `current_role: Optional[str]` — the lead's current job title. * `current_company: Optional[str]` — the lead's current employer. * `location: Optional[str]` — the lead's primary city. * `years_at_company: Optional[int]` — number of years at current employer. * `education: Optional[str]` — highest degree and institution. * `contact_email: Optional[str]` — primary contact email address. Convert this model into a JSON Schema via `LeadProfile.model_json_schema()` and pass the resulting dict to the export request. * Submit the export job with `client.create_memory_export(schema=..., filters=...)` where `filters` is a v2-style AND filter over all three entity IDs (`user_id`, `agent_id`, `run_id`). * The export job runs asynchronously on the server. If the export response is wrapped (e.g. under `data`, `export`, or `result`), unwrap it before saving. * Capture the script's stdout to `/home/user/mem0-export-task/output.log`.
